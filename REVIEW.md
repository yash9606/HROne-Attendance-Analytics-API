# Review of the starter

The starter is `app/main.py` from the candidate kit. Line numbers below refer to that file. The happy path can return a document, but several helpers compute the wrong attendance numbers, and the writes are not safe under concurrency.

| # | Where | What is wrong | How you'd notice it | How it was fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes`, lines 33-37 | Grace is applied to already-floored minutes (`minutes > 10`). A punch at 09:40:01 is 10 floored minutes, so it returns 0. The rule wants 10: late only when the punch is strictly more than 10:00 after shift start, then whole minutes since the shift start. | Shift 09:30, punch 09:40:01. Also 09:40:00.900 must be truncated to 09:40:00 before the test, which this function never does. | Truncate to whole seconds, compare elapsed seconds with 600, then integer-divide by 60. |
| 2 | `compute_late_minutes`, lines 33-37 | Shift start is `punch_in.replace(hour, minute)` on whatever clock `fromtimestamp` used. It is not an IST shift bound, and an overnight shift is not moved to the attendance date. | On a UTC host, 10:05 IST is 04:35 UTC. Replacing the hour with 09:30 compares the punch with 09:30 UTC, so a late morning punch looks early and `late_minutes` stays 0. | Build the shift window in IST from the attendance date, convert to UTC, then subtract. |
| 3 | `compute_work_hours`, lines 40-41 | `round(seconds / 3600, 2)` is binary-float rounding and Python's half-even `round`. | 3618 seconds is 1.005 hours. `round(3618/3600, 2)` returns `1.0`. Half-up must return `1.01`. | Divide `Decimal(seconds) / Decimal(3600)` and quantize with `ROUND_HALF_UP`. |
| 4 | `compute_overtime`, lines 44-47 | The shift end is built on `date_str` only, so an overnight end (06:00) sits on the morning the shift started. It also returns every positive minute, with no 30-minute minimum. The end is IST-aware while punch timestamps from `fromtimestamp` are naive, so the subtraction raises `TypeError` once punch-out calls it. | 22:00-06:00, punch out 06:40 next day. A same-calendar-day end makes the overtime about a day. A 18:35 punch against an 18:30 end returns 5 instead of 0. | Resolve both bounds in IST, add a day when `shift_end <= shift_start`, and keep overtime only when the floored minutes are at least 30. |
| 5 | `health`, lines 72-74 | Always returns 200. It never pings MongoDB. | Stop the database. The probe still says `ok`, so a runner starts the suite against a dead server. | `ping`, and return 503 with FastAPI's `{"detail": ...}` body when that fails. |
| 6 | `create_employee`, lines 77-85 | Duplicate protection is check-then-insert, and nothing creates a unique index or handles `DuplicateKeyError`. | Two concurrent creates of `EMP0001` can both pass `find_one` and both insert. | Unique index on `emp_code`, created at startup. The loser is 409. |
| 7 | `create_employee`, lines 77-85 | `created_at = datetime.now()` is a naive local time and is returned as a datetime, so JSON shows an ISO string. `emp_code`, email, shifts, and `joined_on` are not validated. `shift_start == shift_end` is accepted. | `POST /employees` and inspect `created_at`. Send `EMP12`, `09:30`/`09:30`, or `joined_on=2026-7-01`. | Validate with the contract patterns, store a UTC datetime truncated to seconds, and return epoch milliseconds. |
| 8 | `list_employees`, lines 88-96 | `skip = page * page_size` skips the first page. `total` counts the whole collection, ignoring `department`. There is no `emp_code` sort. `page` and `page_size` are unbounded. `created_at` is not converted. | Seed three employees, request page 1, and filter `department`. Page 1 is empty and `total` is too large. `page_size=1000` is accepted. | Skip `(page - 1) * page_size`, sort by `emp_code`, count the filtered query, and cap `page_size` at 100. |
| 9 | `punch_in`, lines 99-121 | A missing employee is not a 404. `emp["shift_start"]` raises `TypeError` and the request becomes a 500. | Punch in `EMP4040`. | Look the employee up first and return 404. |
| 10 | `punch_in`, lines 99-121 | `fromtimestamp` without a timezone uses the host clock. The attendance date is that local date, with no overnight rule and no truncation. Values that look like seconds are accepted. | Punch at 2026-07-06T20:30:00Z (01:30 IST on 7 July). A UTC host stores 6 July. Punch at 05:30 IST on a 22:00-06:00 shift is stored on the new calendar day instead of the shift-start day. `punched_at=1700000000` is accepted. | Require epoch milliseconds, truncate with integer division, and derive the IST attendance date, including the overnight exception. |
| 11 | `punch_in`, lines 99-121 | Any `status` string is stored, including `ABSENT` and `LEAVE`. The duplicate check is check-then-insert. The response adds `id` and leaves `punch_in` as a datetime. | Send `status=BANANA`, then two concurrent punch-ins for the same employee and day. The body contains `id`. | Allow only `PRESENT`, `WFH`, and `ON_DUTY`. Let the unique `(emp_code, date)` index reject the duplicate. Return the contract fields, with instants as epoch milliseconds and no id. |
| 12 | `list_attendance`, lines 123-150 | The handler loads every match, sorts in Python, and only sorts by date, so ties are not ordered by `emp_code`. Each item exposes `id`. Nested datetimes stay datetimes. | Seed two employees on the same day plus enough rows to matter. The page is slow, the tie order is unstable, and a history timestamp is not epoch milliseconds. | Count, sort, skip, and limit in MongoDB on `(date desc, emp_code asc)`. Serialize the contract shape. |
| 13 | `list_attendance`, lines 123-150 | `date_from > date_to`, a bad date, an unknown status, and `page_size` above 100 are not rejected. | `date_from=2026-07-31&date_to=2026-07-01`, `status=SICK`, `page_size=500`. | Return 422 for an inverted range, a non-canonical date, a status outside the enum, and a page size outside 1..100. |
| 14 | `MongoClient`, line 22 | The client is not `tz_aware`. BSON dates come back naive, so IST arithmetic cannot subtract them from aware shift bounds. | Read a seeded punch and compare it with an IST shift end. | One client for the process, `tz_aware=True` with UTC. Close it on shutdown. |
| 15 | Startup | No indexes are created. The seeded database only has `_id`. List and analytics at ~100k rows collection-scan, and the duplicate checks have nothing underneath them. | `GET /attendance` and a duplicate punch after a restart that skipped the Python check. | `ensure_indexes()` in the FastAPI lifespan, idempotent, before the app reports healthy. |
| 16 | Lines 153-162 | Punch-out, regularization, the four analytics routes, and explain are absent. | Those paths return 404. | Implemented from `openapi.yaml`: conditional punch-out, compare-and-swap regularization with a history append, aggregation pipelines, and `explain` with `executionStats`. |

## Examined and retained

- The IST offset on line 25 is the right one: UTC+05:30. The late and overtime helpers did not use it.
- `load_dotenv()` does not override real environment variables. That matches the deployment rule, so it stayed.
- Default shifts `09:30` and `18:30` match the contract.
- Punch-in already chose the natural key `(emp_code, date)` and initialized `punch_out` and `work_hours` to null, overtime to 0, `half_day` to false, and `history` to `[]`. That shape matches the data model. The defects were the date calculation, the missing unique index, and the response encoding.
- `list_attendance` sliced with `(page - 1) * page_size`. That formula is right. `list_employees` used a different, wrong one.
- The list envelope `{items, total, page, page_size}` matches the contract. `total` in `list_attendance` happened to count the filtered rows, but only after the whole result had been pulled into memory.
